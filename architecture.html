Factory Inventory Management System

System Architecture & Technical Overview

Tech Stack

Frontend

  • Vue 3 (Composition API)
  • Vite — dev server & bundler
  • Vue Router — client-side routing
  • Axios — HTTP client
  • Custom SVG charts (no chart lib)
  • Scoped CSS, CSS Grid / Flexbox
  • i18n — English & Japanese

Backend

  • Python 3.14
  • FastAPI — REST API framework
  • Pydantic v2 — data validation
  • Uvicorn — ASGI server
  • pytest + FastAPI TestClient
  • CORS open for all origins (dev)

Data Layer

  • No database — JSON files on disk
  • Loaded into memory at startup
  • Changes don't persist (restart to reload)
  • 7 datasets: inventory, orders, demand, backlog, spending, transactions, purchase orders

Key Design Decisions

1
Global state via composable singleton — no Vuex or Pinia

Filter state (selectedPeriod, selectedLocation, selectedCategory, selectedStatus) lives as module-level ref() variables in useFilters.js. Because ES modules are singletons, every view that imports the composable shares the same reactive references — no store boilerplate needed.

2
All filtering happens server-side

The frontend never filters data locally. It passes filter values as query params to the API, which filters the in-memory Python lists and returns only matching records. This keeps Vue components simple: raw data in ref(), derived data in computed().

3
In-memory data — no database

All seven JSON datasets are loaded once into Python lists at server startup via mock_data.py. There's no ORM, no migrations, and no persistence — restarting the server reloads the original data. This makes the project self-contained and zero-config.

4
Custom SVG charts — no chart library dependency

All charts (donut, horizontal bar, trend bars) are hand-rolled SVG computed from reactive Vue data. This removes a major dependency and keeps the bundle small, at the cost of more verbose template code.

5
Filter value "all" means no filter applied

Both the frontend and backend treat the string "all" as a sentinel meaning "no filter". The API checks if param and param != 'all' before filtering. This avoids nullable query param ambiguity and keeps URL params readable.
